1. Deep ViewportManager Module

Files: src/main.ts (1,867 lines), src/renderer.ts

⚠️ Problem (Architectural Friction)

src/main.ts currently instantiates and manages 6 individual TerrainRenderer instances, manually handles WebGL resize observers, canvas layout toggles, camera sync loops, and animation frame updates. This spreads WebGL lifecycle complexity across top-level UI code.

✨ Solution (Deepening)

Extract a deep ViewportManager module as defined in CONTEXT.md. It encapsulates 3D canvas grid orchestration, camera synchronization, and WebGL rendering behind a simple high-leverage interface: viewportManager.render(params, mode).

Leverage: Collapses ~350 lines of imperative DOM canvas wiring into 1 interface method. Locality: 3D orbit sync and viewport resize bugs isolated to single deep module.
Worth Exploring

2. Zero-GC Flat Buffer Evaluation in TerrainAlgorithm

Files: src/algorithms/terrain-algorithm.ts, src/algorithms/*.ts

⚠️ Problem

TerrainAlgorithm.generate() allocates nested 2D arrays (number[][]) on the heap every frame. Renderer and Worker then flatten this array back into Float32Array, creating unnecessary GC pressure and conversion overhead.

✨ Solution

Add a zero-GC flat evaluation contract: evaluateFlat(outBuffer: Float32Array, res: number, params: TerrainParams) directly on TerrainAlgorithm.

Leverage: Directly populates GPU vertex buffers and worker transfer buffers without intermediate allocations. Locality: Aligns fully with CONTEXT.md Flat Heightmap Evaluation principle.
Worth Exploring

3. Thin UIManager Adapter for DOM & State Sync

Files: src/main.ts, src/state.ts

⚠️ Problem

main.ts queries 40+ DOM inputs/labels, attaches inline event listeners, and manages mobile control sheet transitions directly.

✨ Solution

Encapsulate DOM bindings in a dedicated UIManager adapter that binds UI controls bidirectionally to the State Observable.

🎯 Top Recommendation

We recommend tackling Candidate 1: Deep ViewportManager Module first. It provides the highest architectural leverage by consolidating 6 WebGL viewport renderers, camera sync loops, and resize observers into a clean deep module, shrinking src/main.ts dramatically while keeping the codebase AI-navigable and highly testable.
